# 数据字典 pricelift

本文件是数值、单位、时间、空值与去重规则的唯一说明处；页面只展示列名与数字，
不放说明段落。

## 1 数值

| 项 | 类型 | 单位 | 精度 | 规则 |
|---|---|---|---|---|
| 含税单价 | Decimal | 元/件 | 4 位 | 先去千分位与全角，再按盒规折成元/件 |
| 不含税单价 | Decimal | 元/件 | 4 位 | `含税单价 ÷ (1 + 税率)`，四舍五入 |
| 销量 | int | 件 | 整数 | 0 是有效值；负数隔离；哨兵不是 0 |
| 销售额 | Decimal | 元 | 2 位 | `不含税单价 × 销量`，逐行量化后累加 |
| 弹性 | Decimal | 无量纲 | 6 位 | 对数线性斜率 `b`，负值表示降价增量 |
| 标准误 | Decimal | 无量纲 | 6 位 | `sqrt(SSE/(n-2)/Sxx)` |
| t 值 | Decimal | 无量纲 | 4 位 | `b / SE(b)`；`|t| ≥ 1.96` 记显著 |
| R² | Decimal | 无量纲 | 4 位 | `1 - SSE/SST` |
| 增量 | Decimal | 元 / 件 | 2 位 / 4 位 | `实际 − 基线` |

金额与销量一律用 Decimal 计算，禁止 float 累加；对外 JSON 中金额与单价是字符串，
销量是整数，避免二进制误差与 2^53 问题。

## 2 单位

- 价格基准单位是 `元/件`。包装单位换算写在 `app/config.py` 的 `PACK_SIZE`：
  1 箱 = 12 件、1 打 = 6 件、1 盒/袋 = 1 件。
- 含税与不含税是两套价：契约里只存「含税单价」与「税率」，不含税价是派生的，
  不再回写原始列。
- 税率白名单 `0.09 / 0.13`（也接受 `9% / 13%`）；不在白名单按 0.13 折算并记
  `P_TAX_UNKNOWN` 提示。

## 3 时间

- 促销区间 **左闭右开** `[开始日期, 结束日期)`：`结束日期` 当天不计入。
  相邻两版首尾相接时（v1 结束 10-19、v2 开始 10-19）10-19 只归 v2。
- 基线窗口是促销最早开始日之前的 14 个自然日 `[开始日 − 14, 开始日)`。
- 建模窗口是日销文件里出现过的日期区间 `[最晚日, 最早日]`，落在窗口外的行记
  `Q_OUT_OF_WINDOW`。本期样例数据无时区列，日期按 `Asia/Shanghai` 的自然日理解。

## 4 空值

空值分三态，语义不同、处理不同：

| 形态 | 表示 | 处理 |
|---|---|---|
| `null` | 单元格不存在 | 必需列缺失记 `Q_MISSING_FIELD`，其余列按空串 |
| 空串 | 单元格长度为 0 | 同 `null` |
| 哨兵 | `-`、`--`、`—`、`/`、`n/a`、`null`、`未知`、`无`、`待定`、`未填`… | 记 `P_SENTINEL_PRICE` / `P_SENTINEL_QTY` 并隔离，**不当 0** |

哨兵清单只在 `app/config.py` 的 `SENTINELS` 定义一次。

## 5 去重与冲突

- 业务键 = `(商品编码, 渠道, 日期)`。同键多条时按文件行号定序保留**首见行**，
  其余进隔离区（`Q_DUP_DAY`），并给出被保留行的行号。
- 促销版本键 = `(促销编号, 版本)`。同一天被多版覆盖时**版本号大者生效**，
  与文件里的书写顺序无关；重叠天数记 `Q_PROMO_OVERLAP`。
- 促销状态只有 `生效` 参与测算；`作废` 与 `待审` 不生效，整体没有生效版本时记
  `Q_PROMO_NO_VERSION`。

## 6 模型与判定

- 样本：同商品同渠道一天一条；`x = ln(不含税单价)`。
- 0 销量两种处理：
  - `shift`（默认）：`y = ln(销量 + 0.5)`，所有点统一平移，0 销量点保留；
  - `drop`：`y = ln(销量)`，0 销量点剔除并单独计数。
- 估计门槛：样本数 ≥ 6 且价格至少 2 个不同取值；否则记
  `L_SAMPLE_TOO_SMALL` / `L_NO_PRICE_VARIATION` 并跳过该组。
- 显著性是 `|t| ≥ 1.96`；不显著的组保留点估计，结论列写「不显著」。
- 基线：`促销前 14 天日均 × 有效天数 × 对照组同期倍数`，其中
  `对照组同期倍数 = 对照组在促销期的日均 / 对照组在基线期的日均`。
- 增量：`实际 − 基线`，金额保留 2 位。
- 区间：`SE(增量) = 基线价 × 基线销量 × |Δln p| × exp(b·Δln p) × SE(b)`，
  上下界取 `增量 ± 1.96 × SE(增量)`；`SE(b) = 0` 时区间收成一点。

## 7 对账

| 账目 | 恒等式 |
|---|---|
| 行账 | 数据记录 = 入模行 + 剔除行 |
| 天数账 | 促销天数 = 有效天数 + 缺日天数 + 剔除天数 |
| 金额账 | 实际销售额 = 基线销售额 + 增量销售额 |
| 促销账 | 促销总数 = 已测算 + 被阻断 + 未生效 |
| 分摊账 | 增量合计 = 各渠道分摊合计 |

分摊用最大余额法：先把总额换成最小单位（0.01 元）取整下沿，剩下的单位按余数从大到小
逐份补，因此分摊合计恒等于总额。
## 8 空态

| 形态 | 结论码 | 说明 |
|---|---|---|
| 0 字节 | `E_EMPTY_FILE` | 导出任务可能没跑成功 |
| 仅表头 | `E_HEADER_ONLY` | 导出条件把数据过滤掉了 |
| 有行但一行都不合法 | `E_COLUMN_COUNT` | 文件结构与表头不匹配 |
| 末行半行 | 422 `E_TRUNCATED_TAIL` | 整批拒绝，不留半批数据 |

## 9 运行清单

`run_id`（`PL-时间戳-随机`）、`batch_key`（样例集 + 0 销量方式 + 规则版本 + 三份输入
sha256 的摘要）、`input_digest`（三份输入 sha256 的摘要）、`rule_version`、
`elapsed_ms`、各阶段进/出/隔离计数。同 `batch_key` 重跑复用已有批次，不新增行。

## 10 实验设计

设计只回答「下一期跑多少天、能识别多大的效应、用哪个对照」，所有数字都由历史日销算出来。

| 项 | 单位 | 精度 | 规则 |
|---|---|---|---|
| 统计单位 | 天 | 整数 | 同商品同渠道一天的销售额合计为一条样本，不是一条明细行 |
| 日均 μ | 元 | 2 位 | 历史窗内日销售额的算术平均 |
| 日波动 σ | 元 | 2 位 | 样本标准差，分母 `n−1` |
| 变异系数 cv | 无量纲 | 4 位 | `σ / μ`，换商品不用重调参数 |
| 稳健方差放大 | 倍 | 4 位 | `max(1, (SE_HC1 / SE_朴素)²)`；HC1 的肉是 `Σ e_i²·(x_i − x̄)²` |
| 系数 k | 无量纲 | 4 位 | `z(1 − α/2) + z(功效)`；α=0.05、功效=0.8 时 k = 2.8016 |
| 最小实验期 n | 天 | 整数 | `n = (A² + sqrt(A⁴ + 4·A²·m))/2` 向上取整，`A = k·cv/目标效应`，`m = 14` |
| 预算下功效 | 无量纲 | 4 位 | `Φ(Δ/SE − z) + Φ(−Δ/SE − z)`，`Δ/SE = 目标效应·n/(cv·sqrt(n+m))` |
| 可识别效应 | 相对值 | 4 位 | `k·cv·sqrt(n+m)/n`：给定天数能识别的最小相对效应 |
| 预期区间 | 元 | 2 位 | `μ·目标效应·n ± z·σ·sqrt(n+m)·sqrt(放大倍数)` |

规则说明：

- **实验窗**左闭右开 `[开始日, 开始日 + 天数)`，天数 = `max(预算天数, 最小实验期)`；
  开始日默认取日销窗口最后一天的下一天。
- **缺日三补法**：`drop` 只算有记录的天；`zero` 缺日按 0 元；`mean` 缺日按同序列日均补。
  三种各算一遍，区间是否含 0 不一致或所需天数极差超过 10% 记 `D_IMPUTE_SENSITIVE`。
- **前置趋势差** = `|ln(对照后半段/前半段) − ln(目标后半段/前半段)|`，只在促销开始前的
  干净窗口里比（不足 6 天则退回全窗口并记 `D_SHORT_HISTORY`）；超过 0.10 记 `D_CONTROL_TREND`。
- **对照选择优先级**：可用 → 偏差 → 不可比 → 排除；同状态内已登记在 `CONTROL_MAP` 的优先，
  再按前置趋势差从小到大。实验期内有自有促销的候选直接判「排除」（`D_CONTROL_OVERLAP`）。
- **目标效应**接受 `0.05` 与 `5%` 两种写法，取值必须落在 `(0, 1]`；α 在 `(0, 0.5)`，
  功效在 `[0.5, 1)`，预算天数 1-180 的整数，越界一律 422 并给原因码。
